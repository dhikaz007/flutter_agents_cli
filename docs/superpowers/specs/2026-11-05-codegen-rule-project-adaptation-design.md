# Codegen rule project adaptation — design

Date: 2026-11-05
Status: approved
Predecessor: `2026-11-05-network-rule-project-adaptation-design.md`
Scope: profile `vibe-coding-rules`, concern `codegen`

## Problem

`templates/rulesets/vibe-coding-rules/rules/CODEGEN.md` installs the same
text for every project. Its two `TEMPLATE-PROJECT:` markers are never filled
by any code:

- line 29, `Localization generation (TEMPLATE-PROJECT: keep only commands
  used by the project):` — the commands below it are hard-coded
  `easy_localization` invocations.
- line 111, `TEMPLATE-PROJECT default:` above a canned startup order
  (`dotenv → EasyLocalization → storage → configureDependencies → observers
  → runApp`) that may not match `lib/main.dart`.

A project such as LMS-ECampus gets a codegen rule that does not describe its
toolchain or its real startup order.

## Decision

Approach 1 (approved): a parallel module pair exactly mirroring the shipped
network design — `codegen_probe.dart` + `codegen_adaptation.dart`, with a
second `if (concern == 'codegen')` branch beside the existing network branch
in the generator's concern loop. No refactor of the released network code;
no registry abstraction until a third adapted concern actually exists.

## Design

### 1. Probe — `lib/src/codegen_probe.dart`

`CodegenProbe.detect(Directory project)` returns `CodegenFacts`:

- `packages`: names from `pubspec.yaml` (dependencies and
  dev_dependencies) matching `build_runner`, `freezed`,
  `json_serializable`, `flutter_gen`, `easy_localization`, `slang`,
  `retrofit`, in that canonical order.
- `annotations`: entries of `(name, path)` for the first file found
  containing each of `@freezed`, `@JsonSerializable`, `@MappableClass`,
  `@RestApi`, scanned from `lib/**/*.dart` excluding `*.g.dart` and
  `*.freezed.dart`.
- `startupOrder`: names detected in `lib/main.dart`, ordered by their
  character position in the source, from the candidate list `dotenv`,
  `EasyLocalization`, `configureDependencies`, `configure_dependencies`,
  `runApp`. Only literals that occur are listed; the order is the file's
  real order.
- `usesLocalization`: `true` when `easy_localization` is a dependency, or
  `assets/translations/` exists, or any generated localization artifact
  exists (`lib/translations/` directory or a file whose name contains
  `locale_keys`).
- `translationFolder`: the detected translation folder relative to the
  project root (`assets/translations` preferred, then `lib/translations`),
  or `null` when neither exists — used to name the folder in the marker
  answer and the section.

Empty lists and `startupOrder == []` are valid; the probe reports only what
it reads and never guesses. `usesLocalization == false` together with empty
`packages`/`annotations`/`startupOrder` makes the facts empty.

### 2. Transform — `CodegenAdaptation.apply(String ruleText, CodegenFacts facts)`

Same contract as the network transform:

1. When `facts.isEmpty`, return `ruleText` byte-identical.
2. **Inline markers.** Two marker shapes exist in CODEGEN.md, each matched
   by its own pattern:
   - parenthetical marker: the text `(TEMPLATE-PROJECT: …)` inside a line
     (line 29 is `Localization generation (TEMPLATE-PROJECT: keep only
     commands used by the project):`). The whole parenthetical is replaced
     by `(answer)` where the answer is
     `Resolved: keep only the easy_localization commands — used (assets/translations)` when
     `usesLocalization` is true (naming the detected translation folder when
     `assets/translations/` exists), else
     `Not detected — drop the localization commands below.`
   - line marker: a line matching `^[\s*-]*TEMPLATE-PROJECT\b` (line 111 is
     `TEMPLATE-PROJECT default:` — note there is no colon after the marker
     word). The marker through end of line is
     replaced by `Resolved: startup order in lib/main.dart —` followed by
     `startupOrder.join(' → ')` when `lib/main.dart` was read and holds at
     least two of the candidate steps, else
     `Not detected — decide the startup order manually.`
   - any remaining occurrence of the literal `TEMPLATE-PROJECT` →
     `Not auto-detected — decide manually.`
3. **Reality section.** When any fact group is non-empty, append:

   ```markdown
   ## Project reality (generated by flutter-agents)

   - Codegen packages: build_runner, freezed, json_serializable (pubspec.yaml)
   - Annotations: `@freezed` — lib/..., `@JsonSerializable` — lib/...
   - Startup order (lib/main.dart): dotenv → EasyLocalization → configureDependencies → runApp
   - Localization generation: used (assets/translations)  |  not used
   - Regenerated on sync. To customize, add a project rule for this concern
     instead of editing this file.
   ```

   Only non-empty groups appear. `Startup order` appears only when
   detected; `Localization generation` appears whenever the facts are
   non-empty.

The localization command block after marker line 29 is NOT rewritten —
the marker verdict plus the section is the shipped scope (a ponytail
ceiling: filter the block itself only when a project misreads it).

### 3. Integration — `lib/src/generator.dart`

Beside the existing `if (concern == 'network')` branch in the ruleset
concern loop:

```dart
if (concern == 'codegen') {
  dynamicBytes = utf8.encode(CodegenAdaptation.apply(
    String.fromCharCodes(dynamicBytes),
    CodegenProbe.detect(project),
  ));
}
```

Both the plain and the merged branch receive the adapted bytes. No other
concern changes.

### 4. Tests — `test/codegen_probe_test.dart`

- Fixture: pubspec with `build_runner`/`freezed`/`json_serializable`/
  `easy_localization`, `lib/main.dart` with the four startup literals in a
  stated order, a file with `@freezed` and one with `@JsonSerializable`,
  `assets/translations/en.json` → `CodegenFacts` correct (order, first
  paths, `usesLocalization`).
- `CodegenAdaptation.apply`: both markers replaced with resolved answers;
  reality section appended; empty facts → byte-identical; missing
  `main.dart` → startup marker says "decide manually".
- Integration: `RuleGenerator().apply` with a ruleset shipping a `codegen`
  concern → `docs/dynamic-rules/rules/CODEGEN.md` and
  `docs/dynamic-rules/merged/codegen.md` both carry the section, markers
  gone.
- Existing suite stays green.

### 5. Acceptance

Copy LMS-ECampus to a temp directory (`rsync` excluding `build`/
`.dart_tool`/`ios/Pods`), run `ruleset use vibe-coding-rules
flutter_modular_v6` then `ruleset apply vibe-coding-rules codegen` with an
isolated `HOME` (the machine's cached ruleset is stale — pre-existing), and
show the produced `CODEGEN.md`. Verify two cited paths in the copy. The
real project is never written to.

## Non-goals

- Rewriting the localization command block itself.
- Other concerns' `TEMPLATE-PROJECT:` markers (UI, SECURITY, ENVIRONMENT).
- No registry abstraction, no new CLI command, no router changes.
